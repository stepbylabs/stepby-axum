# Axum 后台管理项目全局开发规则
## 核心目标
在当前 stepby-axum 目录下，构建 **纯 Axum 0.8 + SeaORM 1.1** 生产级后端服务，接口对齐本项目前端 stepby-vue 调用规范，可直接联调运行。
仅允许修改 stepby-axum 和 stepby-vue 目录。

## 开发优先原则（严格按从高到低执行）
1. **接口契约第一**：接口路径、请求方法、入参出参、分页格式、统一返回结构，严格对齐本项目接口契约（以 stepby-vue 前端调用规范与既有接口定义为准），保证无缝对接；字段类型优先从 stepby-vue 的 TS 定义中提取
2. **架构规范第二**：工程分层、目录结构、编码风格、中间件实现、错误处理、状态注入，遵循 Axum 官方最佳实践并保持与既有工程结构一致
3. **同栈细节第三**：SeaORM 查询写法、事务处理、定时任务/数据权限的实现细节，遵循 Axum + SeaORM 原生惯例，保持与既有模块同栈一致
4. **边界补充第四**：业务规则、异常处理、级联逻辑存疑时，对齐业界通用做法，并用 Axum + SeaORM 原生方式实现

## 绝对禁令（违反视为无效输出）
1. 禁止引入 rbatis 或其他非 SeaORM 的 ORM 运行时依赖和特有 API（如 rbatis 注解式查询），全程统一使用 Axum + SeaORM 原生方式
2. 禁止直接复制粘贴任何外部项目或框架的源码，所有逻辑必须用 Axum + SeaORM 原生方式重新实现
3. 禁止混合多种 ORM 写法，全程统一使用 SeaORM 进行数据库操作
4. 禁止在 Service 层、数据层引入任何 Axum/Web 相关类型，严格遵循单向分层依赖
5. 禁止引入冗余的高耦合功能（如过度数据缓存、多部门切换、中间件函数抽象等），保持职责单一与轻量化实现
6. 禁止修改 stepby-vue 前端核心接口逻辑，后端必须主动适配前端约定

## 分层开发规范
1. Handler 层：仅负责参数解析、服务调用、结果封装，不包含任何业务逻辑
2. Service 层：承载全部业务逻辑、事务控制、参数校验，不依赖任何 Web 层类型
3. Repository 层：封装数据库查询操作，仅与 SeaORM 交互
4. 依赖方向：Handler → Service → Repository，禁止反向依赖

## 输出规范
1. 所有代码按「文件相对路径 + 完整代码块」格式输出，可直接一键创建文件
2. 代码符合 Rust 社区最佳实践，核心逻辑添加必要注释，错误处理完善，命名统一使用蛇形命名法
3. 每次生成完成后，必须按以上规则自查，在末尾标注「✅ 自查结果」，说明是否存在违规点与风险点
